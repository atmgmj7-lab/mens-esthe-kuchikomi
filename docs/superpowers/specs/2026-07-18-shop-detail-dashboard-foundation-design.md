# Eskomi 店舗詳細ダッシュボード基盤 設計書

作成日: 2026-07-18
対象: `headless/` の店舗詳細、口コミ集計、店舗情報表示、対象外店舗の公開除外
採用案: 検証済みデータだけを使う軽量ダッシュボード付き1カラム構成
公開データ元: WordPressを維持
停止条件: ローカル実装・全幅QA・独立レビュー完了後、新しいpush・本番公開前で停止

管理・AI取込・セラピスト連動は、共通のWordPress IDと公開view modelを使う別設計書`2026-07-18-ai-content-admin-therapist-design.md`に定める。

## 1. 目的

Hot Pepper Beautyの情報設計を主軸に、店舗詳細を「情報量が多くても迷わない」1カラムページへ再構築する。上部には参考動画のダッシュボード表現を小さく取り入れ、承認済み口コミ、確認済み店舗情報、既存ランキングを短時間で把握できるようにする。

次の4点を同時に達成する。

1. 口コミを店舗名・画像・予約導線の直後に置き、Eskomiの主コンテンツとして目立たせる。
2. 店舗情報、料金、こだわり、アクセス、基本情報を1カラムと二層のページ内メニューで整理する。
3. メニュー、セラピスト、出勤、店舗ブログ、セラピストブログ、有料店舗情報を将来追加できるmodule境界を作る。
4. グラフは確認済みデータの視覚補助に限定し、本文、見出し、出典、内部リンクをサーバーHTMLへ残してSEOと表示速度を守る。

## 2. 今回実装する範囲

検討した進め方は次の3案である。

| 案 | 内容 | 判断 |
|---|---|---|
| A 検証済みデータ優先 | 口コミ、確認状況、既存順位、1カラムUIを先に作り、将来module境界を用意 | 採用。最短で表示品質を上げ、推測値を防げる |
| B 自動取得優先 | 他ポータルと各店舗公式サイトを巡回し、評価・順位・セラピストを先に集める | 見送り。取得規約、HTML変更、誤照合、保守負担が大きい |
| C 店舗会員基盤優先 | 認証、無料・有料plan、店舗編集、審査を先に完成させる | 後工程。正確性は高いが、現在の店舗詳細UI改善が遅れる |

Aを実装し、Cを次の保存・運用基盤として進める。Bは公開APIまたは個別許諾を確認できた情報源だけ、月次更新connectorとして後から追加する。

## 3. 採用する画面構造

ページ全体は1つの本文カラムとする。PC上部で画像とprofile情報を横並びにしても、右sidebarを持つ2カラムlayoutにはしない。profile、dashboard、tableは最大1200px、紹介文と口コミ本文は最大960pxで中央配置する。

表示順は次のとおりとする。

1. パンくず。
2. 店舗画像、店舗名、地域、料金、営業時間、アクセス、確認日。
3. Web予約、LINE、電話、公式サイトの実在する操作。
4. 二層のページ内メニュー。
5. 口コミsnapshot dashboard。
6. 最新の承認済み口コミと投稿導線。
7. 店舗情報の確認状況とEskomi内順位。
8. 店舗紹介、確認済みおすすめポイント。
9. 料金・メニュー。
10. こだわり・特徴。
11. 地図・アクセス。
12. 基本情報。
13. 近隣店舗・同じ地域・選び方への内部リンク。
14. 店舗責任者向け登録・修正導線。

口コミ0件ではgraphを表示せず、「承認済み口コミはまだありません」と投稿導線を表示する。1〜2件では実在する口コミを表示し、「評価グラフは承認済み評価3件以上で表示します」と案内する。

## 4. 二層ページ内メニュー

見た目はtabだが、SEOとアクセシビリティのため実体は同一ページのanchor navigationとする。contentをJavaScriptで非表示にする`role=tab`構成にはしない。

### 第一層

- 口コミ
- 店舗情報
- 料金・メニュー
- セラピスト
- 地図・アクセス

### 第二層

- こだわり
- 出勤情報
- 店舗ブログ
- セラピストブログ
- 基本情報

第一層は主要な意思決定項目、第二層は詳しく知りたい人向けの補足項目とする。現在の実装では、遷移先となる公開データが存在する項目だけ表示する。

- PCは1行に収まる場合は中央寄せ、収まらなければ横スクロール。
- スマホは左右16pxを維持した横スクロール。
- scrollbarは完全に隠さず、右端のfadeと次項目の一部表示で続きがあることを伝える。
- 現在位置を下線と`aria-current=location`で示す。
- 固定headerとmenuを考慮したscroll offsetを実測する。
- キーボード操作、focus ring、`prefers-reduced-motion`を維持する。

## 5. 口コミ評価dashboard

### 5.0 口コミの公開正本

口コミの正本はWordPress `reviews`投稿typeとする。Supabaseへ公開用の複製を作らず、Next.jsのserver adapterが、専用の読取RESTから次の条件を満たす口コミだけを同じview modelへ変換する。

- WordPressで公開済みかつ`approval_status=approved`。
- 公開関係の正本であるWordPress店舗IDが一致。slug不一致は管理警告にし、当該店舗の旧slug履歴と確認できた場合だけ表示する。
- 公開fieldは本文、投稿日、`rating_total`、`rating_price`、`rating_service`、`rating_cleanliness`だけ。
- 投稿者email、管理memo、審査状態の内部情報を返さない。

店舗詳細のgraph、最新口コミ、件数、AggregateRatingは必ずこの共通view modelを使う。上部には最新3件までを表示し、4件目以降は`/shops/{slug}/reviews/`のページ分割された口コミ一覧へつなぐ。

### 5.1 表示条件

集計対象は次をすべて満たす口コミだけとする。

- sourceがユーザー投稿。
- WordPressで承認済み。
- 公開状態。
- 対象店舗IDが一致。
- 本文が存在。
- 1〜5点の有効な評価値。

総合評価graphは有効な総合評価が3件以上の場合だけ表示する。料金、接客、清潔感は各項目の有効回答が3件以上の場合だけ、その棒を表示する。未回答の0を評価0として集計しない。

店舗紹介文、編集部コメント、AI文章、PR文章、WordPressの件数だけの参考値、他サイト評価はEskomi口コミgraphへ混ぜない。

### 5.2 表示内容

- 左: 総合評価を5点満点で示す小型ring graph。
- 右: 総合、料金、接客、清潔感の横棒。
- 下: 承認済み口コミ件数、対象期間または最新投稿日、3件以上を集計する説明。
- その下: 最新口コミを最大3件表示し、残りは専用の口コミ一覧へつなぐ。

ringと横棒には数値を文字でも併記する。色だけで差を伝えない。screen readerには「接客 4.3点、回答5件」のように読めるlabelを付ける。

### 5.3 視覚表現

参考動画から次を取り入れる。

- 白いpanelと薄いborder。
- 余白のある大panel内にgraphと数字をまとめる。
- 指標名、数値、分母、補足の4段階の文字hierarchy。
- 小さな状態chip。
- 横棒の下に具体的件数を併記。

動画の大型日別推移graph、期間filter、複数表示mode、tooltip、一覧操作は初期版へ入れない。Eskomiの濃緑、金、生成り、本文色を使い、動画の青・赤・橙・緑をそのまま持ち込まない。

## 6. 店舗情報の確認状況

これは店舗品質の採点ではなく、Eskomiが確認できた情報の範囲を示す。

対象項目は次の6件とする。

1. 料金。
2. 営業時間。
3. 駅・アクセス。
4. 予約先。
5. 公式サイト。
6. 店舗画像。

表示は「確認済み 5/6」のような件数、横棒、項目ごとの確認済み・未確認labelとする。「優良」「低評価」「情報不足店」などの価値判断には使わない。最新の確認日は点数へ含めず、確認済みfieldの`reviewedAt`から`latestReviewedAt`を補足表示する。

確認日はWordPressの有効な日付がある場合だけ表示する。公式サイトが存在しても各項目の出典が確認できない場合は、公式サイトの存在だけを確認済みとし、料金等の出典済みとは扱わない。

確認状態はページ全体の更新日だけで判定しない。WordPressの`shop_fact_provenance`に、料金、営業時間、アクセス、予約先、公式サイト、画像ごとの`sourceUrl`、`sourceType`、`observedAt`、`reviewedAt`、`reviewStatus`、`publishedValueHash`を保存する。現在の公開値hashが`publishedValueHash`と一致し、`reviewStatus=reviewed`の項目だけを確認済みに数える。`shop_updated_at`はページ全体の公開更新日として残し、各項目の確認日の代用にはしない。

## 7. Eskomi内順位

既存の公開ランキング情報がある場合だけ表示する。

- 順位。
- 対象地域。
- 並び順またはランキング名。
- PR・手動指定などの既存開示。
- `observedAt`。
- 対象店舗総数`totalEligibleShops`。
- 算定根拠`basis`。

WordPressの順位snapshotは`areaSlug`、`rank`、`totalEligibleShops`、`basis`、`observedAt`、`isPr`を必須契約とする。WordPress配列の位置、乱数、口コミ不足時の仮評価から順位を作らない。順位がない店舗ではcard自体を表示しない。

## 8. 将来moduleの境界

店舗詳細は、表示可能なmoduleをview modelで組み立て、画面はその順番を描画する。

各moduleは少なくとも次を持つ。

- 一意なsection ID。
- menu label。
- 第一層または第二層。
- 見出し。
- 表示可能な確認済みデータ。
- 公開範囲。
- 出典または情報提供者。
- 確認日。

表示範囲と編集権限を分離する。公開moduleは`visibility: public | unlisted | private`、入力者は`authoringEntitlement: admin | owner-free | owner-paid`、審査方法は`moderationPolicy: review-required | trusted-publish`を持つ。無料・有料は入力可能範囲であり、審査済みcontentの閲覧範囲ではない。承認済みで`visibility=public`のcontentは会員planに関係なく全利用者へ表示し、審査前入力は公開しない。

将来追加する主なmoduleは次のとおり。

| module | 初期の正本 | 公開条件 |
|---|---|---|
| セラピスト | 店舗責任者または運営の確認入力 | 審査済み・公開指定 |
| 年齢層 | 公開セラピストの年代集計 | 合計3名以上 |
| 在籍数 | 公開セラピスト件数 | 確認日あり |
| 出勤 | 店舗責任者入力 | 日付・確認時刻あり |
| 店舗ブログ | 店舗責任者投稿 | 審査または公開権限あり |
| セラピストブログ | 対象セラピスト投稿 | 審査または公開権限あり |
| 他ポータル評価・順位 | 管理者確認入力から開始 | 出典URL・対象地域・確認日あり |

セラピスト、在籍数、年齢層、出勤は、WordPress `therapist`投稿typeと`therapist_schedule`だけを公開正本にする。既存の`therapist_1..3`、店舗年齢帯meta、`shop_today_therapists`は移行・互換入力に限定する。同名のセラピストもWordPress therapist IDが異なれば別人として扱う。

年齢帯graphは公開対象3名以上の場合だけ表示する。1区分が1〜2名になる場合は隣接区分へまとめるか「その他」へ統合し、少人数から個人の年齢を推測できない表示にする。

## 9. 表示速度

- graph libraryを追加しない。
- ringはSSRされたinline SVGまたはCSS、横棒はCSSで描画する。
- graph用client componentを作らない。
- 初期表示後の追加API requestを行わない。
- 口コミと店舗情報は既存のWordPress取得結果からview modelを生成する。
- 店舗詳細、店舗一覧、地域、トップ、セラピスト詳細は、同じWordPress IDと共通public adapterを使い、画面別のmeta解釈を作らない。
- animationは原則使わず、使う場合もopacityとtransformだけに限定し、`prefers-reduced-motion`で停止する。
- 画像の4:3、適切な`object-fit`、既存fallbackを維持する。
- 新しいnpm依存関係を追加しない。
- mobile fixed actionとページ内menuが本文を隠さない。

## 10. SEO

- 店舗名はページ唯一の`h1`。
- 口コミ、料金、店舗紹介、アクセス、基本情報は内容がある場合に`h2`を持つ。
- graphの数値と説明をHTML文字として出力する。
- graphだけで情報を伝えず、表または文章による同等情報を併記する。
- anchor navigationで全sectionを同じHTMLへ保持する。
- canonical、パンくず、LocalBusiness、AggregateRatingの既存契約を維持する。
- AggregateRatingは承認済み口コミ3件以上の場合だけ出力する。
- 口コミ本文と店舗提供情報を出典labelで分離する。
- 内部リンクは同じ地域、近隣地域、料金、口コミ、選び方へ具体的なanchor textでつなぐ。
- 空tab、空section、準備中だけの薄いcontentをindex用に作らない。

セラピスト詳細は、公開状態、所属店舗、画像または確認済み紹介、確認日がすべてある場合だけindex可能にする。パンくずはホーム→地域→店舗→セラピスト、canonicalとsitemap、店舗詳細との相互linkを必須とし、条件を満たさないrecordには公開routeを作らない。

ダッシュボードはSEO本文を置き換えるものではなく、検索ユーザーが情報を短時間で理解するための補助UIとする。

## 11. 対象外店舗の整理

読み取り監査で次の2店舗を対象外と確定した。

| WordPress ID | 店舗名 | 現在の状態 |
|---:|---|---|
| 1259 | あしぎぬ温泉 | `shop`として公開・index可能 |
| 1255 | 天然温泉 ひなたの湯 | `shop`として公開・index可能 |

処理はWordPressで`draft`へ変更する。最初から完全削除やごみ箱移動は行わず、戻せる状態を維持する。

公開後に次を確認する。

- WordPress公開店舗RESTから消える。
- 店舗一覧と地域一覧から消える。
- sitemapから消える。
- 店舗詳細が200を返さない。
- canonicalとLocalBusinessが出力されない。
- 件数表示が2件分減る。
- 内部監視dataの次回生成対象から除外される。

既存URLのSearch Console流入や外部linkが確認できた場合は、内容が近いメンズエステページへ誤った301転送をせず、404または410の扱いを別途決める。

## 12. 8月SEO目標との関係

2026年8月31日までに優先地域の対象検索語で10位以内を目標とする。ただし検索順位は外部要因があるため達成を保証せず、次の管理可能な先行指標を追う。

- 対象外店舗0件。
- 優先地域の公開店舗に、料金、営業時間、アクセス、予約先、公式サイト、画像、確認日のうち確認済み項目を増やす。
- 空本文、空地域説明、架空口コミを増やさない。
- 店舗詳細から地域・口コミ・料金・選び方への内部link欠落0件。
- 店舗詳細の横はみ出し0、重複CTA 0。
- Search Consoleで地域×メンズエステ系queryの表示回数、click、平均掲載順位を週次確認する。
- 10位以内へ近い地域から一次情報と独自本文を優先投入する。

UI公開後の次工程は、34地域を同時に薄く更新するのではなく、Search Consoleの表示回数と現在順位で優先地域を選び、店舗の一次情報・画像・独自紹介・地域内比較を深くする。

## 15. 検証条件

### 自動検査

- 口コミ3件未満ではgraphが出ない。
